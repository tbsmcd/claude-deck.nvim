1. INTRODUCTION                                              *claude-deck-intro*

claude-deck.nvim runs Claude Code in Neovim terminals. Each terminal
shows its id, status and task title in the winbar, its cwd and session id
in the statusline, sends a desktop
notification when it waits for you, and lets Claude inspect the other
terminals with the `ct` command.

Requires Neovim 0.11 or later and `claude` on PATH. The hook script and
`ct` call `nvim --server`, so `nvim` must also be on the PATH seen by Claude
Code.

Optional (everything works without them):
- fzf-lua: pickers with split keys; falls back to |vim.ui.select()|
- nvim-tree.lua: file tree in focus mode; falls back to netrw
- zoxide: extra directories in |claude-deck.pick_dir()|
- jq: pretty-prints the JSON of |claude-deck.show_settings()|
- terminal-notifier (macOS, `brew install terminal-notifier`): desktop
  notifications that bring back the terminal app when clicked
- otherwise osascript (macOS, with lsappinfo for the frontmost app check),
  notify-send (Linux) or the terminal's own notifications for desktop
  notifications, or your own `notify.notifier`
  (|claude-deck-notify|)

2. SETUP                                                     *claude-deck-setup*

>lua
    require("claude-deck").setup({})
<
No keymaps are created. Map the functions below, for example:
>lua
    local ct = require("claude-deck")
    vim.keymap.set("n", "<leader>cc", ct.toggle)
    vim.keymap.set("n", "<leader>cv", function() ct.new("right") end)
    vim.keymap.set("n", "<leader>cs", function() ct.new("below") end)
    vim.keymap.set("n", "<leader>cl", ct.list)
    vim.keymap.set("n", "<leader>cd", ct.pick_dir)
    vim.keymap.set("n", "<leader>cf", ct.fork)
    vim.keymap.set("n", "<leader>cr", ct.rename)
    vim.keymap.set("n", "<leader>co", ct.focus)
    vim.keymap.set({ "n", "x" }, "<leader>cp", ct.send_location)
<
`send_location()` can also be mapped with `keymaps.send_location`.

3. USAGE                                                     *claude-deck-usage*

                                                                  *:ClaudeDeck*
:ClaudeDeck [{subcommand} [{args}]]
    Without a subcommand, same as `toggle`.

toggle()                                                  *claude-deck.toggle()*
    Outside a terminal, focus a visible terminal or open a new one. Inside a
    terminal, open a new one to the right.

new({where})                                                 *claude-deck.new()*
    Open a new terminal. {where} is "right" or "below" to split the current
    window, or nil to use the default placement:
    - inside a terminal: to the right
    - in an empty unnamed buffer: in place
    - otherwise: at the far right
    The new terminal uses the current terminal's cwd, or |getcwd()|.

list({opts})                                                *claude-deck.list()*
    Pick a terminal, including hidden ones, and show it. With fzf-lua,
    <CR> opens with the default placement, <C-v> splits right and <C-s>
    splits below. {opts}.where sets the placement for |vim.ui.select|.

pick_dir({opts})                                        *claude-deck.pick_dir()*
    Pick a directory and open a new terminal there. Candidates, in order:
    the current directory, its children, cwds of terminals, children of
    `dir_roots`, and zoxide. Hidden directories (names starting with ".")
    are skipped among children, but not in terminal cwds or zoxide.
    With fzf-lua, the keys to open are the same as in |claude-deck.list()|,
    and this picker also lets you browse directories:
      <Tab>     go into the selected directory: list it (to open there)
                and its children
      <S-Tab>   go up: list the parent and its children (from the first
                list, the parent of the current directory)
    When nothing matches, <Tab> shows the same list again.
    With |vim.ui.select| only the first list is shown.

fork({where})                                               *claude-deck.fork()*
    Open a new terminal that runs `claude --resume <session> --fork-session`
    for the current terminal's session.

rename()                                                  *claude-deck.rename()*
    Rename the current terminal's task. This title takes precedence over
    the one Claude sets with `ct title` (|claude-deck-ct|).

redraw()                                                  *claude-deck.redraw()*
    Draw the current terminal again at the current window width: stop
    Claude Code and resume the same session with
    `claude --resume <session>` in a new buffer in the same window. The
    terminal keeps its number and title. Only while Claude is waiting for
    input (or has exited); it takes a few seconds. Use it to clean up the
    stale output fragments of the classic renderer
    (|claude-deck-limitations|).

focus()                                                    *claude-deck.focus()*
    Inside a terminal, open a new tab with file tree | editor | terminal and
    |:tcd| to the terminal's cwd. In that tab, close it and return to the
    original window.

send_location()                                    *claude-deck.send_location()*
    Made for focus mode (|claude-deck.focus()|): in the editor, insert the
    current file path and line into Claude's prompt and move to the
    terminal, to go on typing your instructions. It also works outside
    focus mode when exactly one terminal is shown in the current tab.
    `:ClaudeDeck location` does the same (with a range, e.g. `:'<,'>`, it
    sends those lines).
    - normal mode: the cursor line, e.g. `app/services/example.rb:24`
    - Visual mode (|v|, |V| or |CTRL-V|): the selected lines, e.g.
      `app/services/example.rb:24-58`
    The path is relative to the terminal's cwd (outside it: absolute, with
    "~" for the home directory) and is followed by a space. A path with
    spaces is inserted as it is, without escaping. Nothing is submitted: no
    <CR> is sent, and only the path and line numbers go in, even when the
    file has unsaved changes.
    The location goes to the terminal of the focus mode in that tab;
    outside focus mode, to the terminal shown in the current tab when there
    is exactly one. Otherwise, and for buffers that are not files (unnamed,
    inside a terminal) or a terminal that has exited or is not shown in the
    tab, nothing is inserted and a message tells why. In the diff buffer of
    `ct diff`, the file and line under the cursor are sent.
    Map it in both normal and Visual mode (see |claude-deck-setup|), or set
    `keymaps.send_location`.

open_file({path}, {line}, {id})                      *claude-deck.open_file()*
    Open {path} in the editor window of the focus mode of terminal {id}
    and make that window current (in normal mode), with the cursor on
    {line} if given (past the end: the last line). Without focus mode for
    the terminal, open focus mode first (showing the terminal if it is
    hidden). A relative {path} is relative to the terminal's cwd. Without
    {id}: the current terminal, or the terminal of the focus mode tab.
    Directories are refused. A file with a swap file is opened read-only.
    `:ClaudeDeck open {path}[:{line}]` does the same, with a relative path
    relative to Neovim's current directory. `ct open` runs this
    (|claude-deck-ct|).

open_diff({opts})                                    *claude-deck.open_diff()*
    Open a diff in the editor window of the focus mode of terminal
    {opts.id} (default: the current terminal, or the terminal of the focus
    mode tab), opening focus mode first when needed: the diff of the pull
    request of the current branch (`gh pr diff`), otherwise the uncommitted
    changes (`git diff HEAD`); with {opts.base}, the working tree compared
    with that ref (`git diff {base}`). With {opts.path} (relative to the
    terminal's cwd), the cursor goes to that file, and with {opts.line} to
    that line of the new side. See |claude-deck-ct| for the diff buffer.
    `:ClaudeDeck diff [{path}[:{line}]] [--base {ref}]` does the same, with
    a relative path relative to Neovim's current directory. `ct diff` runs
    this.

show_settings()                                    *claude-deck.show_settings()*
    Show the Claude Code settings JSON (hooks and `ct` permissions) in a
    scratch buffer. Use it to add the hooks to your own settings when
    `claude_settings` is false.

show({id}, {where})                                         *claude-deck.show()*
    Show terminal {id}.

Closing a terminal window with |:q| hides it; Claude keeps running. Bring it
back with |claude-deck.list()| (`:ClaudeDeck list`).

This also holds for the last window: |:q| (and |ZZ|, |CTRL-W_q|, |:x|) leaves
Neovim open with an empty window, and a message tells how many terminals are
still running. Use |:qa| to quit Neovim. |:q| again in the empty window quits
Neovim too, ending every Claude session. Turn this off with
`keep_alive_on_quit = false`.

                                                           *claude-deck-windows*
Keys typed in a terminal go to Claude. Leave terminal mode with <C-q>
(`keymaps.normal_mode`) or <C-\><C-n>, then use |CTRL-W| commands. Moving
back into a terminal window enters terminal mode (`auto_insert`). Set
`keymaps.window = "<C-w>"` to run window commands from terminal mode (Claude
Code's CTRL-W, delete word, is then unavailable).

<C-]> sends <Esc> to Claude (`keymaps.send_esc`): interrupt, close dialogs;
twice for <Esc><Esc>. Useful if you map <Esc> to leave terminal mode.

Opening a terminal does not resize other windows, even with 'equalalways'.

                                                       *claude-deck-scrolling*
Scrolling back ~

Claude Code has two renderers; claude-deck uses the classic one by default
(`renderer`).

classic (default): the whole conversation stays in the terminal buffer.
Leave terminal mode (<C-q>) and use Neovim: |j| / |k|, |CTRL-U| / |CTRL-D|,
|gg| / |G|, |/| to search, |v| and |y| to copy. Press |i| to go back to the
prompt.

fullscreen: Claude Code keeps the history and the buffer only holds the
current screen. Scroll inside Claude Code: PageUp / PageDown (Fn+Up /
Fn+Down on a Mac), Ctrl+End for the latest, Ctrl+O for the transcript view
(j / k, / to search), or the mouse wheel.

                  classic                       fullscreen
    Flicker       may flicker while writing     none
    Prompt input  follows the conversation      always at the bottom
                  (near the top until it
                  fills the window)
    History       terminal buffer (up to        kept by Claude Code; the
                  `scrollback` lines)           buffer holds one screen
    Scroll,       Neovim normal mode            PageUp / PageDown, Ctrl+O
    search, copy  (j / k, /, y)                 transcript, mouse wheel
    Mouse clicks  handled by Neovim             handled by Claude Code
    Long          redraw leftovers may pile up  stays fast; only the
    conversations as duplicate lines in the     visible part is drawn
                  scrollback
    Window        stale output fragments may    whole screen is redrawn
    resize        remain

Set `renderer = "fullscreen"`, or `renderer = false` to follow your Claude
Code settings (`tui`). The renderer is passed with CLAUDE_CODE_NO_FLICKER
(0 for classic, 1 for fullscreen), which takes precedence over `tui`. The
change applies to terminals opened afterwards.

With `renderer = false` the environment variable is not changed: if
CLAUDE_CODE_NO_FLICKER is set in Neovim's environment, Claude uses it;
otherwise Claude Code's `tui` setting decides.

4. STATUS AND NOTIFICATIONS                                 *claude-deck-status*

Status comes from Claude Code hooks registered with `claude --settings`, so
your own settings are not modified. With `claude_settings = false`, add the
hooks to your own settings (|claude-deck.show_settings()|); otherwise
status, notifications, task titles and fork do not work.

    New        started, `SessionStart`
    Running    `UserPromptSubmit`, `PostToolUse`
    Waiting    `Stop`                        (notifies)
    Needs you  `Notification`                (notifies)
    Exited     the process exited

Waiting means Claude finished its turn and waits for your next prompt (it
is not queued or about to run). Needs you means Claude is blocked in the
middle of a task until you answer a permission prompt or a question.

By default (when cli.enabled, cli.system_prompt and cli.auto_title are all
on), Claude names its terminal with `ct title` once it understands the task
(|claude-deck-ct|). Until then, the task title is the beginning of the first
prompt (slash commands are ignored). A title set with |claude-deck.rename()|
takes precedence. `/clear` resets the title, except one set with rename().

A notification is skipped when Neovim has focus, the current window shows
that terminal and, on macOS, the terminal app is the frontmost app.

Notifications are sent after a short delay (`notify.delay`, 2 seconds by
default). If Claude resumes in the meantime, nothing is sent. This covers
Claude finishing its turn while it waits for a background process and
continuing by itself when the process ends.

                                                            *claude-deck-notify*
`notify.method` chooses how notifications are sent. `notify.notifier`, when
set, takes precedence.

    "auto"               (default) "terminal-notifier" if installed,
                         otherwise "osascript" on macOS; "notify-send" on
                         Linux
    "terminal-notifier"  macOS. Clicking the notification brings back the
                         terminal app running Neovim. A newer notification
                         of the same terminal replaces the older one.
    "osc"                the terminal emulator shows the notification (OSC 9
                         escape sequence, supported by iTerm2 among
                         others). Clicking it brings back the terminal.
                         Allow notifications in the terminal's settings
                         (iTerm2: Profiles > Terminal > Notifications).
                         Does nothing in a GUI or with --headless.
                         Inside tmux, OSC 9 does not reach the outer
                         terminal.
    "osascript"          macOS, built in. Clicking the notification does
                         NOT bring back the terminal app.
    "notify-send"        Linux

On macOS, install terminal-notifier (`brew install terminal-notifier`) so
that clicking a notification takes you back to Neovim; "auto" then uses it.
If the command of the chosen method is not found, setup() warns once and
uses "auto". `:checkhealth claude-deck` shows the method in use and whether
clicking a notification brings back the terminal.

If terminal-notifier shows nothing on macOS, allow it in System Settings >
Notifications (the permission prompt may not appear the first time). When a
notification command fails, Neovim shows a warning with the reason, once per
command per session.

5. THE CT COMMAND                                               *claude-deck-ct*

Inside a terminal, `ct` is on PATH and Claude is told about it:

    ct list                 list terminals
    ct read <id> [count]    recent messages of a terminal (default 20)
    ct title [title]        set the task title of this terminal; without a
                            title, show it
    ct title --force title  also replace a title set with rename()
    ct open path[:line]     open a file in the editor of focus mode
    ct diff [path[:line]] [--base ref]
                            open the diff of the pull request (or of the
                            uncommitted changes) there

All of them are allowed without a permission prompt. `ct read` parses Claude
Code's transcript files, whose format is internal and may change.

With `cli.auto_title`, Claude is told to name its terminal with `ct title`
as soon as it understands the task, with a short title in the language of
your prompt, and to rename it when the task changes. A title may be at most
40 cells wide (display width); a longer one is refused, not cut, so that
Claude picks a shorter one. A title set with |claude-deck.rename()| takes
precedence: `ct title` refuses to change it, and Claude uses
`ct title --force` only when you ask it to rename the terminal.

`ct open` opens a file in the editor window of the terminal's focus mode
(|claude-deck.open_file()|), opening focus mode first when needed. A
relative path is relative to the current directory of Claude's shell, and
`path:line:col` uses only the line. A file whose whole name matches (e.g.
`foo:24`) is opened as it is. A file with a swap file is opened read-only.
Claude is told to use it when you ask it to open or show a
file, or to show you the code it is explaining: e.g. "open app/index.html"
or "show me line 24 of greeter.rb".

`ct diff` opens a diff in that editor window (|claude-deck.open_diff()|), as
a read-only buffer with the `diff` filetype: the diff of the pull request of
the current branch (`gh pr diff`; needs the GitHub CLI `gh` and a pull
request), otherwise the uncommitted changes (`git diff HEAD`). With
`--base ref`, the working tree is compared with that ref (`git diff ref`),
without looking for a pull request. The first line of the buffer names the
source. With a path, the cursor goes to that file's section, and with a
line to that line of the new side (a line outside the hunks: the nearest
hunk header); a file without changes is refused. Keys in the diff buffer:

    <CR>        open the file under the cursor at that line in a window
                right of the diff (the diff stays; `ct open` while a diff
                is shown opens the file beside it too)
    ]f  [f      next / previous file
    ]c  [c      next / previous hunk
    q           close the window

|claude-deck.send_location()| in the diff buffer sends the file and line
under the cursor. Claude is told to use `ct diff` when you ask to see a
diff, the changes or the pull request, or to show you a change it is
explaining: e.g. "show me the diff of this PR" or "show me the change in
greeter.rb".

6. CONFIGURATION                                           *claude-deck-config*

    cmd                   command to start Claude  (default: { "claude" })
    claude_settings       pass hooks and `ct` permissions with
                          `claude --settings`  (default: true)
    title_width           max characters kept for the task title; the
                          winbar cuts it to fit  (default: 60)
    statusline            cwd and session id in the window's statusline;
                          false puts the cwd in the winbar  (default: true)
    width_ratio           width of a terminal opened at the far right
                          (default: 0.4)
    dir_roots             directories whose children `pick_dir()` offers
    zoxide                also offer zoxide directories  (default: true)
    labels                text for each status and `untitled`
    notify.enabled        (default: true)
    notify.states         (default: { "waiting", "attention" })
    notify.skip_when_watching  (default: true)
    notify.delay          milliseconds to wait before sending; 0 sends at
                          once  (default: 2000)
    notify.method         "auto", "terminal-notifier", "osc", "osascript"
                          or "notify-send"; see |claude-deck-notify|
                          (default: "auto")
    notify.notifier       function({ title, subtitle, body, state, terminal })
    keymaps.normal_mode   terminal-mode key to leave terminal mode
                          (default: "<C-q>", false to disable)
    keymaps.window        terminal-mode prefix for window commands
                          (default: false, e.g. "<C-w>")
    keymaps.send_esc      terminal-mode key that sends <Esc> to Claude
                          (default: "<C-]>", false to disable)
    keymaps.send_location global normal / Visual mode key for
                          |claude-deck.send_location()|
                          (default: false, e.g. "<leader>cp")
    renderer              "classic", "fullscreen" or false to leave
                          CLAUDE_CODE_NO_FLICKER as it is in Neovim's
                          environment (unset: Claude Code's `tui`); see
                          |claude-deck-scrolling|  (default: "classic")
    scrollback            'scrollback' of terminal buffers (max 100000),
                          false to leave it  (default: 100000)
    auto_insert           enter terminal mode when entering a terminal
                          window  (default: true)
    keep_alive_on_quit    |:q| on the last window hides a running terminal
                          instead of quitting Neovim  (default: true)
    picker                "auto", "fzf-lua" or "select"
    focus.tree            "auto", false or function(cwd)
    cli.enabled           put `ct` on PATH and allow it  (default: true)
    cli.system_prompt     tell Claude about `ct`  (default: true)
    cli.auto_title        tell Claude to name its terminal with `ct title`;
                          `ct title` works either way  (default: true)

7. HIGHLIGHTS                                          *claude-deck-highlights*

The default status colors are based on the Okabe-Ito palette and differ in
lightness as well as hue, so they stay distinguishable with color vision
deficiencies. All are defined with `default = true` and can be overridden.

    ClaudeDeckIdle         gray
    ClaudeDeckRunning      sky blue
    ClaudeDeckWaiting      yellow
    ClaudeDeckAttention    vermillion
    ClaudeDeckExited       dark gray
    ClaudeDeckCwd          links to |hl-Directory|

8. LIMITATIONS                                        *claude-deck-limitations*

- Interrupting Claude does not fire `Stop`; the status stays Running until
  the next prompt.
- On macOS, switching tabs or panes inside the terminal app is not detected
  as losing focus.
- Terminals are lost when Neovim exits: |:qa| (or |:q| on a window that is
  not a running terminal) ends every Claude session without asking.
- |:q!| and |ZQ| discard the terminal buffer, which ends that Claude session
  even when Neovim stays open.
- With the classic renderer, when the window gets narrower (for example
  when focus mode opens), Claude Code may fail to erase part of its earlier
  output, so fragments of stale output (such as the tail of a line) can
  remain in the scrollback. This is how the classic renderer behaves in any
  terminal when it is resized; the plugin cannot prevent it, and Ctrl+L does
  not remove the fragments. New output and the prompt are drawn correctly.
  If you resize windows often, use `renderer = "fullscreen"`; otherwise
  return to the main tab after focus mode and let Claude print something,
  and drawing is normal from then on. To clean up the fragments, run
  |claude-deck.redraw()| while Claude is waiting for input: it stops Claude
  Code and resumes the same session with `claude --resume` in the same
  window, so the whole conversation is drawn again at the current width.
  It takes a few seconds.
